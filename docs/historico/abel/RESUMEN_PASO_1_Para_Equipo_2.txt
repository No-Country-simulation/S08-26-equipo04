📌 CONCEPTOS BÁSICOS (5 minutos de lectura)

🔑 CLAVE PRIMARIA (PK)
├─ Es el "DNI" o "pasaporte" de cada fila en una tabla
├─ Debe ser ÚNICO (no se puede repetir)
├─ No puede ser NULL (debe tener valor)
└─ Ejemplo: CLIENTE.id = 1, 2, 3... (cada cliente tiene un ID único)

🔗 CLAVE FORÁNEA (FK)
├─ Es una "referencia" que apunta a la PK de otra tabla
├─ Vincula dos tablas entre sí
├─ Garantiza la integridad de los datos
└─ Ejemplo: SOLICITUD_TRABAJO.clienteId = 1 (apunta a CLIENTE.id = 1)

🔄 TIPOS DE RELACIONES

┌─────────────────────────────────────────────────────────────────────────┐
│ 1️⃣  UNO A MUCHOS (1:N) - La más común                                   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│   CLIENTE (1) ──────────→ SOLICITUD_TRABAJO (N)                          │
│                                                                           │
│   Un cliente puede tener MUCHAS solicitudes de trabajo                   │
│   La FK va en la tabla "muchos": solicitud_trabajo.cliente_id            │
│                                                                           │
│   Ejemplos en QualityTrack:                                              │
│   • 1 Cliente → N Solicitudes                                            │
│   • 1 Solicitud → N Cotizaciones                                         │
│   • 1 Orden de Trabajo → N Operaciones                                   │
│                                                                           │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ 2️⃣  UNO A UNO (1:1)                                                      │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│   COTIZACION (1) ──────────→ ORDEN_TRABAJO (1)                           │
│                                                                           │
│   Una cotización genera exactamente UNA orden de trabajo                 │
│   La FK va en la tabla "dependiente": orden_trabajo.cotizacion_id        │
│                                                                           │
│   Ejemplos en QualityTrack:                                              │
│   • 1 Cotización → 1 Orden de Trabajo                                    │
│   • 1 Orden de Trabajo → 1 Entrega                                       │
│                                                                           │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ 3️⃣  MUCHOS A UNO (M:1) - Especial: Múltiples registros → Un registro   │
├─────────────────────────────────────────────────────────────────────────┤
│                                                                           │
│   OPERACION (N) ──────────→ USUARIO (1)                                  │
│                                                                           │
│   MUCHAS operaciones pueden asignarse a UN usuario (operario)            │
│   UN usuario puede supervisar MUCHAS órdenes de trabajo                  │
│                                                                           │
│   En QualityTrack:                                                       │
│   • N Operaciones → 1 Usuario (responsable)                              │
│   • N Órdenes → 1 Usuario (supervisor)                                   │
│   • N Quality Checks → 1 Usuario (inspector)                             │
│                                                                           │
└─────────────────────────────────────────────────────────────────────────┘

📊 EL FLUJO COMPLETO DE QualityTrack

┌──────────────┐
│   CLIENTE    │  (Un cliente solicita trabajo)
│  (id = PK)   │
└──────┬───────┘
       │ 1:N (cliente_id FK)
       │
       ↓
┌──────────────────────────────────┐
│  SOLICITUD_TRABAJO               │  (Cliente describe qué necesita)
│  (id = PK, cliente_id = FK)      │
└──────┬───────────────────────────┘
       │ 1:N (solicitud_trabajo_id FK)
       │
       ↓
┌──────────────────────────────────┐
│  COTIZACION                      │  (Empresa da precio y plazo)
│  (id = PK, solicitud_id = FK)    │
└──────┬───────────────────────────┘
       │ 1:1 (cotizacion_id FK)
       │
       ↓
┌──────────────────────────────────┐
│  ORDEN_TRABAJO                   │  (Cliente aprueba, sale a planta)
│  (id = PK, cliente_id, cotiz_id) │
│  (responsable_id FK → USUARIO)   │
└──────┬───────────────────────────┘
       │ 1:N (orden_trabajo_id FK)
       │
       ├──→ HOJA_RUTA               (Divide el trabajo en pasos)
       │    │ 1:N
       │    └──→ OPERACION          (Cada paso específico)
       │         (responsable_id FK → USUARIO)
       │         │ 1:N
       │         └──→ QUALITY_CHECK  (Se verifica cada operación)
       │              (inspector_id FK → USUARIO)
       │
       └──→ ENTREGA                 (Trabajo completado, cliente recibe)

💾 EJEMPLO EN SQL (Cómo se crea una tabla con FK)

-- Paso 1: Crear tabla INDEPENDIENTE (sin FK)
CREATE TABLE cliente (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    nombre VARCHAR(100) NOT NULL,
    email VARCHAR(100),
    telefono VARCHAR(20)
);

-- Paso 2: Crear tabla DEPENDIENTE (con FK)
CREATE TABLE solicitud_trabajo (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    cliente_id BIGINT NOT NULL,           ← Esta es la FK
    descripcion TEXT,
    estado VARCHAR(50),

    -- Aquí decimos que cliente_id DEBE existir en cliente.id
    FOREIGN KEY (cliente_id) REFERENCES cliente(id)
);

-- Paso 3: Si intentas algo ilógico → ❌ ERROR
INSERT INTO solicitud_trabajo VALUES (1, 999, 'Descripción', 'PENDIENTE');
                                           ↑
                            No existe cliente con id=999
                            LA BASE DE DATOS LO RECHAZA

-- Paso 4: Hacer correctamente → ✅ OK
INSERT INTO cliente VALUES (1, 'Acme Corp', 'acme@test.com', '1234567');
INSERT INTO solicitud_trabajo VALUES (1, 1, 'Descripción', 'PENDIENTE');
                                           ↑
                        Ahora cliente con id=1 SÍ existe

⚡ PUNTOS CLAVE PARA MEMORIZAR

1. PK (Primary Key) = El DNI de cada registro (único, no NULL)
2. FK (Foreign Key) = La referencia que conecta dos tablas
3. La FK SIEMPRE va en la tabla "muchos" o la tabla "dependiente"
4. La BD valida automáticamente que la FK apunte a un PK que exista
5. Sin FK no hay integridad referencial (se puede tener datos "huérfanos")
6. Con FK sí hay integridad = datos consistentes y confiables
